Yeshiva Shorts Uploader

A personal command-line application that uploads pre-rendered vertical video clips to its operator's own YouTube channel.

Privacy Policy Terms of Service

This is the official home page of the application named “Yeshiva Shorts Uploader” — the same name shown on its Google OAuth consent screen. The application is developed and operated by Roee Pearl, who also owns and controls this website.

The purpose of this application

Recorded Torah lessons are long. Turning one into short vertical clips for YouTube means cutting the clip, burning in Hebrew subtitles, and writing a title, description and tags for each one — work that is done deliberately, offline, before this application is involved at all.

What remains after that is pure repetition: opening YouTube Studio once per clip, selecting a file, and re-typing metadata that already exists in a local file. Yeshiva Shorts Uploader exists to do exactly that last step and nothing else. It reads clips and their metadata from the operator's own disk and submits them to the operator's own YouTube channel through the YouTube Data API.

Every video it uploads is created with private visibility. Nothing becomes publicly visible as a result of running this application; the decision to publish is made separately and manually in YouTube Studio afterwards.

Why it needs access to a Google account

Uploading a video to a YouTube channel requires the channel owner's authorization. The application therefore requests a single OAuth scope, and no others:

  • https://www.googleapis.com/auth/youtube.upload — required to call videos.insert, which is the only API method the application uses. Without this scope the application cannot perform its one function.

This scope grants upload permission only. The application cannot read channel analytics, cannot read or post comments, cannot see subscriber information, and cannot modify or delete videos already on the channel. It requests no access to Gmail, Drive, Contacts, Calendar, or any other Google service. How the resulting credentials are stored and how to revoke them is described in the Privacy Policy.

How it works

  • It runs as a command-line program on the operator's own Windows computer.
  • It has no website interface, no server, no database, and no user accounts.
  • It is not distributed, published, sold, or offered to anyone else. It has one user: its operator.
  • Authorization is granted once, through Google's own consent screen, by the account that controls the target channel.
